# Code of Conduct

## Our standard

SpectreOS contributors are expected to interact professionally and constructively.

Examples of good project behavior include:

- discussing technical issues without personal attacks;
- welcoming questions from people at different experience levels;
- focusing criticism on code, design, evidence, and reproducible behavior;
- acknowledging uncertainty when a subsystem is not yet fully understood;
- giving credit for useful ideas and fixes.

Unacceptable behavior includes harassment, threats, discrimination, deliberate disruption, doxxing, and publishing private information without permission.

## Maintainer response

Project maintainers may remove comments, close discussions, or reject contributions that violate this standard. Technical disagreement by itself is not a violation; disagreements should remain evidence-based and respectful.

## Reporting

Report conduct concerns privately to the repository maintainer through the contact method published on the project's GitHub page. Do not publicly disclose private information about another contributor.

## Scope

This code of conduct applies to project repositories, issue discussions, pull requests, documentation, and other spaces used for SpectreOS development.
